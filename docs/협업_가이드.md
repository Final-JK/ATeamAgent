---

## 1. 프로젝트 개요

CodeFab 교육 과정의 인터프리터 제작 과제입니다.  
C++17로 작성된 트리-워크 인터프리터이며, 다음 두 축으로 설계되었습니다.

- **Expression Node**: 값을 평가하는 노드 (숫자, 연산, 변수 참조 등)
- **Statement Node**: 동작을 수행하는 노드 (출력, 선언, 블록, 제어흐름 등)

**테스트 기준 Gist**:  
`https://gist.github.com/aijeonghwan-star/d1535e870aeb6a4a928142d4d57c191e`

## 3. 빌드 및 실행

### 3-1. 최초 빌드

프로젝트 루트(`C:\Users\...\CustomInterpreter`)에서 실행:

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

성공 시 `out\interpreter.exe` 생성.

### 3-2. 프로그램 실행

```bash
out\interpreter.exe <소스파일.fab>
```

### 3-3. 전체 테스트 실행

```powershell
# PowerShell
Get-ChildItem tests\*.fab | ForEach-Object {
    Write-Host "=== $($_.Name) ===" -ForegroundColor Cyan
    .\out\interpreter.exe $_.FullName
    Write-Host ""
}
```

## 4. 아키텍처

### 4-1. 처리 파이프라인

```
.fab 소스 파일
      │
      ▼
  [Lexer]           문자열 → Token 배열
      │               · 숫자, 문자열, 식별자 인식
      │               · // 주석 무시
      │               · LexError: 인식 불가 문자
      ▼
  [Parser]          Token 배열 → AST
      │               · 재귀하강 방식
      │               · ParseError: 문법 오류
      ▼
  [Resolver]        AST 정적 검사 (스코프 스택)
      │               · StaticError: 자기 초기화 / 중복 선언
      ▼
  [Interpreter]     AST 실행 (Environment 체인)
                      · RuntimeError: 미정의 변수 / 타입 불일치
```

### 4-2. Expression Node 목록

| 클래스 | 코드 예시 | 주요 필드 |
|--------|-----------|-----------|
| `LiteralExpr` | `42`, `"hi"`, `true` | `Value value` |
| `UnaryExpr` | `-x` | `Token op`, `ExprPtr right` |
| `BinaryExpr` | `a + b`, `x < 3` | `ExprPtr left`, `Token op`, `ExprPtr right` |
| `GroupingExpr` | `(1 + 2)` | `ExprPtr expression` |
| `VariableExpr` | `count` | `Token name` |
| `AssignExpr` | `count = 1` | `Token name`, `ExprPtr value` |

### 4-3. Statement Node 목록

| 클래스 | 코드 예시 |
|--------|-----------|
| `PrintStmt` | `print x;` |
| `ExprStmt` | `x = x + 1;` |
| `VarStmt` | `var x = 10;` |
| `BlockStmt` | `{ var a = 1; print a; }` |
| `IfStmt` | `if (x > 0) print "pos"; else print "neg";` |
| `ForStmt` | `for (var i = 0; i < 3; i = i + 1) { print i; }` |

### 4-4. 스코프 규칙

- 변수는 선언된 블록 안에서만 유효하다 (블록 스코프).
- 안쪽 블록에서 바깥 변수를 읽거나 수정할 수 있다.
- 안쪽 블록에서 같은 이름으로 `var` 선언 시 새 변수가 생성된다 (섀도잉).
- `for` 루프의 초기화 변수는 루프 블록 스코프에 한정된다.

## 5. 테스트 케이스

### 5-1. 정상 동작

#### 표현식 / 연산자 / 우선순위

```
print 1 + 2 * 3;        → 7
print (1 + 2) * 3;      → 9
print 10 - 4 - 3;       → 3
print 8 / 2 / 2;        → 2
print -3 + 2;           → -1
print 1 < 2;            → true
print 3 > 5;            → false
print "Hello, " + "CodeFab!";   → Hello, CodeFab!
print 5;                → 5
print 5.0;              → 5
print 3.14;             → 3.14
print true;             → true
print false;            → false
```

> **숫자 출력 규칙**: 정수 값은 소수점 없이 출력 (`5.0` → `5`), 소수 값은 그대로 출력 (`3.14` → `3.14`).

#### 변수 / 스코프 / 섀도잉

```
var a = 10;
var b = 20;
print a + b;            → 30
a = a + 5;
print a;                → 15

var x = "global";
{ var x = "inner"; print x; }  → inner
print x;                        → global

var count = 0;
{ count = count + 1; }
print count;            → 1

var outer = "A";
{ var inner = "B"; { print outer + inner; } }  → AB
```

#### 제어흐름

```
if (true) print "bbq";                          → bbq
if (false) print "no"; else print "kfc";        → kfc
if (true) if (false) print "kfc"; else print "bbq";  → bbq

for (var j = 0; j < 3; j = j + 1) { print j; }
→ 0
  1
  2
```

### 5-2. 에러 케이스

| 파일 | 내용 | 기대 오류 |
|------|------|-----------|
| `err1_missing_semicolon.fab` | `print 1 + 2` | `Syntax Error at end: Expected ';'` |
| `err2_missing_paren.fab` | `print (1 + 2;` | `Syntax Error at ';': Expected ')'` |
| `err3_invalid_assign.fab` | `a + b = 3;` | `Syntax Error at '=': Invalid assignment target.` |
| `err4_bad_expr.fab` | `print * 5;` | `Syntax Error at '*': Expected expression.` |
| `err5_self_init.fab` | `{ var a = a; }` | `Static Error: Can't read local variable in its own initializer.` |
| `err6_duplicate_var.fab` | `{ var a = 1; var a = 2; }` | `Static Error: Already a variable with this name in this scope.` |
| `err7_undefined_var.fab` | `print notDefined;` | `Runtime Error: Undefined variable 'notDefined'.` |
| `err8_type_mismatch.fab` | `print 1 + "HI";` | `Runtime Error: Operands must be two numbers or two strings.` |
| `err9_wrong_operand.fab` | `print -"FabCoding";` | `Runtime Error: Operand must be a number.` |

## 6. 파일별 역할 요약

| 파일 | 역할 | 수정 빈도 |
|------|------|-----------|
| `Token.h` | TokenType enum, Token 구조체, `Value` 타입 정의 | 기능 추가 시 |
| `Lexer.h/.cpp` | 문자 → 토큰 변환, 키워드 테이블 | 키워드 추가 시 |
| `Expr.h` | Expression AST 노드 전체 | 새 표현식 추가 시 |
| `Stmt.h` | Statement AST 노드 전체 | 새 구문 추가 시 |
| `Environment.h/.cpp` | 변수 스코프 체인 | 거의 수정 없음 |
| `Parser.h/.cpp` | 문법 규칙 → AST 생성 | 구문 추가 시 |
| `Resolver.h/.cpp` | 정적 검사 로직 | 검사 규칙 추가 시 |
| `Interpreter.h/.cpp` | 실행 의미론 | 실행 로직 변경 시 |
| `main.cpp` | 진입점, 오류 catch | 거의 수정 없음 |

## 7. Claude와 협업하는 방법

### 7-1. 세션 시작 시 필수 사항

Claude Code를 이 프로젝트 디렉토리에서 실행하면 `CLAUDE.md`가 자동으로 로드됩니다.  
별도의 컨텍스트 설명 없이 바로 작업을 요청할 수 있습니다.

### 7-2. 효과적인 요청 방법

```
# 좋은 예시
"while 루프 문을 추가해줘. for 루프 구현 방식을 참고해서 WhileStmt를 만들어."

# 나쁜 예시
"루프 추가해줘." (무엇을, 어떻게 추가할지 불명확)
```

### 7-3. 팀원 간 작업 분담 권장 방식

| 역할 | 담당 파일 |
|------|-----------|
| 어휘/구문 확장 | `Lexer.cpp`, `Parser.cpp` |
| 새 연산자/표현식 | `Expr.h`, `Interpreter.cpp` |
| 새 제어구문 | `Stmt.h`, `Parser.cpp`, `Interpreter.cpp` |
| 정적 검사 강화 | `Resolver.cpp` |
| 테스트 작성 | `tests/*.fab` |

### 7-4. 주의사항

- 빌드 후 항상 `tests/` 전체 실행으로 회귀 검사 수행
- 새 노드 추가 시 **Resolver와 Interpreter 양쪽** 모두 visit 메서드를 추가해야 컴파일된다
- `Value` 타입(`std::variant`)에 새 타입을 추가할 경우 `stringify()`, `isTruthy()`, `isEqual()` 모두 수정 필요
