# 세션 재시작 가이드 — CustomInterpreter (CodeFab)

**최종 업데이트**: 2026-06-05 (Ch.5 Shell Mode 완료)  
**목적**: 다른 PC 또는 새 세션에서 동일한 컨텍스트로 작업을 재개하기 위한 완전한 가이드  
**중요**: 이 문서는 **저장소 루트 경로가 달라도** 동작할 수 있도록 작성되었습니다.

---

## 1. 전제 조건

| 항목 | 요구 사항 |
|------|-----------|
| OS | Windows 10/11 (x64) |
| 컴파일러 | Visual Studio Build Tools 2022 이상 (`cl.exe`, MSVC 19.x) |
| PowerShell | 5.1 이상 (빌드·테스트 스크립트용) |
| Claude Code | 최신 버전 CLI 또는 Desktop App |

---

## 2. 저장소 설정

```powershell
# 1. 클론 (경로는 원하는 위치로 변경 가능)
git clone <repo-url> CustomInterpreter
cd CustomInterpreter

# 2. 빌드
powershell -ExecutionPolicy Bypass -File build.ps1

# 3. 빌드 확인
out\interpreter.exe tests\test1_expressions.fab
# 기대 출력: 5, 3, 6, -2, 2, true, false, Hello World
```

> **경로 독립성**: `build.ps1`은 스크립트 자신의 위치를 기준으로 동작하므로 어느 경로에 클론해도 무방합니다.

### 4-2. 구현된 기능 전체 목록

**Ch.1 — 기초**
- 숫자/문자열/bool/nil 리터럴, 산술·비교·단항 연산자
- 문자열 연결 (`"a" + "b"`), `print` / `var` / 대입
- 블록(`{}`), `if/else`, `for` 루프
- 정적 검사: 자기 초기화 참조, 동일 스코프 중복 선언

**Ch.2 — 함수**
- `Func name(params) { body }` 선언·호출·return
- 클로저(Lexical Scoping), 재귀 호출
- 정적 검사: 함수 외부 return, 중복 파라미터

**Ch.3 — 정적 배열**
- `Array(n)` 생성, `arr[i]` 읽기/쓰기, 표현식 인덱스
- 런타임 검사: 범위 초과, 비숫자 인덱스, 비배열 대상, 비숫자 크기

**Ch.5 — 실행 모드 (Shell)**
- **InterpreterFactory** (GoF Factory Method 패턴): argc/argv 기반 모드 선택
- **파일 모드**: `interpreter <file>` (기존 동작을 FileRunner로 분리)
- **REPL 모드**: `interpreter` — 대화형, 변수·함수 세션 유지, 오류 후 계속
- **디버그 모드**: `interpreter --debug <file>` — Stmt stepping, breakpoint, watch/inspect

### 4-4. 전체 테스트 실행 명령

## 8. 핵심 설계 결정 요약 (빠른 참조)

### Ch.1 ~ Ch.3

| 결정 | 이유 |
|------|------|
| `return`에 C++ 예외(`ReturnSignal`) | 중첩 블록 탈출, 기존 `catch(...)` 패턴과 일관성 |
| `FabFunction::body` 비소유 포인터 | `FuncStmt`가 AST 소유, `interpret()` 수명 동안 안전 |
| `FabFunction`/`FabArray` forward declaration in `Token.h` | `Value` variant 포함 필요 + 순환 의존성 방지 |
| `Array()`를 `ARRAY_KW` + `ArrayCreateExpr`로 처리 | 내장 함수 대비 타입 검사가 명확 |
| `IndexSetExpr`를 `assignment()`에서 `IndexGetExpr` 재변환 | `arr[i] = v` 구문이 대입 표현식 형태 |
| 클로저: `fn->closure = currentEnv` (선언 시점 캡처) | Lexical Scoping |

### Ch.5

| 결정 | 이유 |
|------|------|
| GoF Factory Method 패턴 | `main.cpp`를 모드 로직에서 분리, 추가 점수 대상 |
| REPL: `Interpreter` 인스턴스 재사용 | `globalEnv`가 세션 전체에서 자동으로 유지됨 |
| REPL: `sessionStmts`로 AST 보관 | `FabFunction::body` 댕글링 포인터 방지 |
| REPL 전역 재선언 허용: 별도 플래그 불필요 | Resolver `declare()`가 `scopes.empty()`일 때 중복 검사 생략 |
| 디버그 훅: `Interpreter::stmtHook` 콜백 | 파이프라인 변경 없이 외부에서 실행 제어 주입 가능 |
| `stmtHook` nullptr 기본값 | 파일/REPL 모드에서 오버헤드 없음 |
