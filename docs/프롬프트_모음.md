## Session 1 — 인터프리터 기초 구현 (2026-06-02)

### Prompt 1-1 : 인터프리터 초기 생성 요청

**의도**: 과제 요구사항을 Claude에게 전달하고 C++ 기초 코드를 생성 요청

```
code review agent 라는 교육의 coursework 을 진행 중이야.
과제를 받았는데, interpreter 를 만들어야 하는 과제야.
테스트 구문은 "https://gist.github.com/aijeonghwan-star/d1535e870aeb6a4a928142d4d57c191e"
를 통과해야 해야 해.
Tree 구조를 이용하여 NODE 를 생성하고, NODE 는 expression node, statement node 로 구분지어야 해.
언어는 C++ 를 이용해서 만들어야 하는데, 기본 코드를 생성해줄 수 있을까?
해당 과제의 설명은 @"1일차_CodeFab Interpreter.pdf" 이야.
```

**Claude의 주요 판단**:
- PDF를 읽고 Gist URL에서 테스트 케이스를 가져와 요구사항 파악
- Crafting Interpreters 스타일의 트리-워크 인터프리터 구조 채택
- `std::variant<double, std::string, bool, std::nullptr_t>`를 `Value` 타입으로 정의
- Visitor 패턴으로 ExprVisitor / StmtVisitor 분리
- 파이프라인: `Lexer → Parser → Resolver → Interpreter`
- 4단계 에러 계층: `LexError`, `ParseError`, `StaticError`, `RuntimeError`
- 숫자 출력 규칙: `5.0` → `"5"`, `3.14` → `"3.14"` (정수는 소수점 생략)
- MSVC 컴파일러용 `/utf-8` 플래그 필요 (한글 주석 처리)

**생성된 파일**:
```

## 효과적인 후속 프롬프트 예시

아래는 다음 단계 기능 구현 시 사용할 수 있는 프롬프트 예시입니다.

### while 루프 추가

```
while 루프를 추가해줘.
- WhileStmt 노드를 Stmt.h에 추가
- Parser에서 "while" 키워드 처리
- Resolver와 Interpreter에 visitWhileStmt 추가
- for 루프 구현 패턴을 참고해서 일관성 있게 만들어줘
- tests/test4_while.fab 파일도 같이 만들어줘
```

### 함수 선언 추가

```
fun 키워드로 함수를 선언하고 호출할 수 있게 해줘.
- FunctionStmt, CallExpr 노드 추가
- 스코프는 클로저 방식 (정의 시점의 환경을 캡처)
- return 값은 Value 타입으로 처리
- 기존 Environment 체인 방식을 유지해줘
```

### 논리 연산자 추가

```
and, or 논리 연산자를 추가해줘.
- 단락 평가(short-circuit) 방식으로 구현
- 결과는 bool이 아니라 피연산자 값 자체를 반환 (truthy 기반)
- BinaryExpr를 재사용하거나 LogicalExpr를 별도로 만들지 판단해줘
```
